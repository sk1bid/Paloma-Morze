Model (S is the APAK reception speed, not words per minute):
  Fs = 11025 Hz, unsigned 8-bit PCM
  dot = roundTiesToEven(66120 / S) samples
  dash = roundTiesToEven(dot * dashRatioTenths / 10) samples
  intra-element silence = dot samples
  tone frequency = 11025 / integerPeriod; period range 8..38
  edge = roundTiesToEven((13-frontPosition) * 11025 / 2000) samples
  sine sample = 128 + roundTiesToEven(127*sin(2*pi*i/period)*linearEnvelope)
  release is inside tone length, never added afterward
  phase restarts at sample zero for every element
  square mode thresholds the intermediate signal to PCM 8/248

Addresses, ImageBase 0x00400000:
  0x0045AD44 tone generation; 0x00461C50 inverted edge slider
  0x0045B324 character assembly, including a final silent dot
  0x0045B584 WAVEHDR length; 0x0045B6CC waveOutWrite wrapper
  0x00461928 interval lookup; 0x0045F74F/0x0045F79C text group/letter timers
  0x0045E5F4 lesson-1 timers: 1500 ms when new group, otherwise 500 ms
  0x0045F8AA repetition timer: Trunc(2*C*pauseTenths/10)

Text/radiogram timers, after the character buffer's final silent dot:
  C = Int.cwl[S/5 - 6], zero-based; calibrated values committed in apakAudio.js
  letter_ms = Trunc(pauseTenths * dot * 1000 / 110250) + C
  group_ms  = Trunc(3 * pauseTenths * dot * 1000 / 110250) + C
  gap samples = dot + roundTiesToEven(timer_ms * Fs / 1000)
This is the programmed timer, not OS/driver overhead. One-sample quantization
of millisecond timers is deliberate. The learning mode uses 500/1500 ms instead;
repeat-after-error uses the repetition timer, all from the same model.

Playback:
One AudioBufferSourceNode holds the entire finite sequence. Only one 20 ms
lead-in is used. UI timers never control the next sound. Parameters are
snapshotted together. Stop resolves pending promises with {cancelled:true},
clears visual events and releases the sound source. Source-named local/remote
keys continue sharing a single sidetone. Reception controls use APAK ranges.
Native sidetone uses the same frequency grid and fixed-time edge, independent
of volume. Human-operated key duration is not a precomputed APAK character;
its edge is applied in realtime and is not claimed sample-identical to a
pre-rendered complete character.

Actual original-program validation:
APAK 2.12 was launched in CrossOver. The user operated the GUI and played
lesson 1, exercise 1, S=50, dash ratio=3, pause=3, mnemonics off.
A disposable instrumented EXE copy logs every waveOutWrite buffer and its
GetTickCount submit timestamp, then forwards the unchanged call to WinMM.
The synthesis code, sequence logic and timers are unchanged. This is PCM
capture before OS mixing, not microphone or system-loopback recording.

The recording identifies period=23 (479.347826 Hz) and frontPosition=6.
All 27 captured characters match the new model byte for byte: zero differing
samples. Unique E, L, V (= Cyrillic Ж), A buffers are the committed golden
fixtures, with settings/provenance in capture.json. They were obtained from
running the original binary, not generated by the tested implementation.

The observed CrossOver sign-to-sign delays also include callback/driver/thread
latency. The captured sequence lasts 43.2645 s; deterministic Paloma learning
playback of the same 27 signs lasts 39.2615 s. The implementation intentionally
models the original PCM and programmed timers, not a particular Wine system's
variable excess latency. This prevents claiming wall-clock playback identity.

Clean playback update (metallic-artifact report)
---------------------------------------------
The default PRACTICE AUDIO setting is now Clean. playbackSignal.js synthesizes
Float32 at AudioContext.sampleRate instead of playing the quantized PCM8 stream
through a 11025-Hz rate conversion. It reuses the original pulse timetable,
frequency grid and edge duration; attack/release endpoints are exactly zero,
inside each element. Conversion of each absolute boundary is <= half an output
sample, without cumulative gap drift. Square uses a band-limited wavetable.
The original byte-accurate mode remains selectable as APAK under Settings.
Golden fixtures continue to test that reference generator, not clean PCM.
Manual keyboard/USB sidetone paths are unchanged by this update.

45 JS tests pass, including default native-rate engine output, preserved timing
at 44.1/48/96 kHz, silent gaps, waveform endpoint continuity and sustained-sine
quantization error. Build and lint of the audio modules pass.
The user's perceived metallic artifact is not yet confirmed eliminated by a
listening test; lower numerical distortion alone is not proof of its cause.

The earlier export-apak-ab.mjs produces ORIGINAL-MODE PCM comparisons. Its
byte-identical aligned result remains valid for that mode. The new default
Clean mode does not claim byte identity with APAK's original PCM8.

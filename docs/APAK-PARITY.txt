APAK-CWL 2.12 audio parity — 2026-11-07

Production choice
All clients request original APAK PCM8 synthesis in the existing C++ engine.
There is no quality selector or second production audio engine. User code maps,
including Paloma's single-dash zero, are unchanged. Custom overrides remain intact.

Source signal
morse_audio.hpp preserves APAK's 11025 Hz, unsigned PCM8 synthesis, integer-period
carrier, rounding, phase restart and inside-element attack/release. Four captured
original waveOutWrite buffers still match the C++ output byte for byte at 11025 Hz.
The former linear device-rate interpolation is replaced with a 20-tap (at rates
>=11025) Kaiser-windowed sinc. Original source quantization is retained; this is
sample-rate conversion, not a clean sine replacement. Coefficients and converted
dot/dash buffers are prepared outside the audio callback. The callback only reads
prepared samples. Live keyboard/USB/remote ownership and cancellation stay intact.

Cadence
Settings::programmedGap retains the disassembled timer and Int.cwl formulas.
Settings::gap adds 232 reference samples (~21.043 ms) at character boundaries,
including group boundaries. Dots, dashes and intra-character silences do not change.
This is a fixed reference cadence matched to observed Windows APAK dispatch overhead,
not a universal OS latency law. It applies consistently in the continuous C++ stream
on all platforms; it does not add synthetic random timing jitter or UI timers.
The extra per-character transition is shared by text, learning and repeat plans;
physical measurements below validate the exercise-4 path. Learning/repeat retain
their own original programmed timer formulas and have deterministic regression tests.

Evidence
ui/tests/fixtures/apak-2.12/windows-cadence.json records fresh-process APAK loopback
measurements at 30, 50, 105 and 150, pause x3, ratio 3, period 23, front 6, Timer on.
Twenty letter gaps and five group/end gaps per speed corroborate a ~21 ms average
transition overhead. Longer original 105 capture adds 40 letter/10 group gaps.
No capture had missing frames or post-initial discontinuities.
An exploratory run that changed the speed control without restarting had stale
synthesis buffers (e.g. displayed 50 but sound at 45). It was discarded for this
calibration. Fresh CWK.dat settings were loaded in a separate APAK process per speed.

Independent waveform regression
windows-105-dash.f32 is an unfiltered, unnormalized steady dash excerpt from real
Windows loopback of the unmodified APAK executable. Its JSON gives exact provenance,
source hash and extraction bounds. C++ tests fit only constant gain and a bounded
integer phase offset, then require relative RMS error <0.12%. Current result: 0.06283%.
The old linear converter fails this test (~0.30%). Exact post-device bit identity
is not claimed: the Windows resampler and device processing remain external.
